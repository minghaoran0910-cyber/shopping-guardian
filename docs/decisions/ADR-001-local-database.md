# ADR-001：本地业务数据使用 Drift/SQLite

- 状态：已采用
- 日期：2026-07-27

## 背景

决策历史、消费规则和预算原本保存在 SharedPreferences。它适合少量设置项，但不适合持续增长的结构化记录：关联数据难以约束，整批 JSON 读取会放大损坏影响，也缺少可靠的事务边界。

## 决策

业务数据改用 Drift/SQLite，并保留 SharedPreferences 仅承载轻量设置。数据库包含：

- 决策主表，以及事件、历史引用、替代方案三张关联表；
- 消费规则表；
- 预算和迁移标记键值表；
- 旧数据损坏记录隔离表。

旧版数据首次访问时自动迁移。迁移在单个事务中完成，成功提交后才删除旧键；无法解析的单条记录进入隔离表，不阻断其他数据。重复旧 ID 会自动添加稳定后缀，避免静默覆盖。

## 取舍

- 优点：支持事务、关系约束、增量查询、Schema 升级和大数据量；
- 成本：增加代码生成步骤及原生 SQLite 依赖；
- 限制：当前隔离记录只用于诊断，尚未提供用户界面。后续导入功能应复用相同的预览、校验和事务机制。

## 验证

- 覆盖正常迁移、损坏决策、损坏规则、重复 ID 和事务回滚；
- 使用真实文件数据库验证关闭重开后数据仍在；
- 使用 5000 条决策验证无记录丢失，并对完整读取设置时间上限。
