# PREF-02 验收记录：确认偏好的来源与反例

日期：2026-07-30
版本：1.9.8+33

## 本轮范围

- 分析请求只包含状态为 `confirmed` 的个人偏好。
- 每条偏好以结构化形式发送：稳定 ID、文本、支持依据、相反记录。
- 发送前核对页和建议结果都展示支持依据与反例。
- 保存决策时一并保存当时引用的偏好证据，便于日后追溯。

## deep-grill 结论

仅在提示词里要求模型“说明来源”并不可靠，因为模型可以编造引用。来源和反例必须由本地数据决定，界面不能直接展示模型自报的证据。

另一个失败场景是删除原始决策后，旧偏好继续引用已经不存在的记录。本轮会按当前决策 ID 过滤证据；没有任何有效支持依据的偏好不会进入请求。候选、忽略项以及来源全部失效的已确认项均不会发送。

## 自动验收

- 请求正文包含结构化偏好、支持依据和相反记录。
- 请求正文与系统提示均禁止省略反例或编造来源。
- 发送前核对页明确展示支持与反例。
- 候选偏好不会出现在确认引用列表。
- 已删除决策对应的证据被移除。
- 失去全部有效支持证据的已确认偏好不会发送。
- API Key 不进入请求正文或偏好证据。
