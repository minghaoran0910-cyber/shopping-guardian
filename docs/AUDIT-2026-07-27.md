# 购物守护者 v1.3.0 审查与验收报告

审查日期：2026-07-27  
审查范围：MRD、PRD、README、产品设计、Flutter 业务代码、平台实现、自动化测试、构建、GitHub CI 与 Release。

## 结论

当前版本适合定位为“技术型早期用户可实际试用的公开 Beta”，暂不建议定义为面向普通用户的稳定 1.0。

核心闭环已经成立：

> 导入商品 → 补充意图 → 模型分析 → 用户决定 → 本地记录 → 冷静期/购买后反馈 → 后续分析引用历史

主要风险不在功能数量，而在数据可靠性、模型兼容性、第三方解析稳定性、隐私说明和跨平台交付完整度。

## P0：稳定 1.0 前必须解决

### P0-1 完整数据清除

当前“清除决策和预算”不会删除消费规则、通知计划、主题/语言和首次启动状态；已经排程的通知可能在清除后继续出现。

验收标准：

- 提供含数据范围说明的“清除全部数据”；
- 删除决策、预算、规则、模型配置、商品 API Key 和通用偏好；
- 取消全部由应用创建的通知；
- 重启后进入首次启动状态；
- 自动化测试逐项验证所有存储为空。

### P0-2 可靠持久化与迁移

决策历史目前存为 SharedPreferences 字符串数组。任意一条 JSON 损坏可能让整批历史无法读取，也不适合继续增加商品、规律、物品和提醒实体。

验收标准：

- 迁移到 SQLite/Drift 或等价的事务型本地数据库；
- 旧数据可自动迁移；
- 单条损坏不影响其他记录；
- 写入失败可回滚；
- Schema 有明确版本；
- 5000 条记录下读写和检索保持流畅。

### P0-3 数据恢复

当前 JSON 只能导出，不能导入，无法作为完整备份。

验收标准：

- 导入前检查 Schema；
- 展示将导入的数据范围；
- 支持合并或覆盖；
- 冲突处理规则明确；
- 失败时不改变现有数据；
- API Key 永不从业务数据包导入。

### P0-4 模型兼容层

当前固定拼接 `/chat/completions` 并强制发送 `response_format: json_object`，“OpenAI-compatible”的实际范围有限。

验收标准：

- 支持标准 OpenAI Endpoint 和完整自定义 Endpoint；
- `response_format` 可关闭；
- 提供 Ollama/常见兼容服务预设；
- 对 429 和 5xx 做有限退避重试；
- 测试连接能区分地址、鉴权、模型名、限流和格式能力问题。

### P0-5 隐私说明

业务数据默认保存在本机，但分析时会把商品、购买理由、预算、命中规则和相关历史摘要发送给用户配置的模型；商品接口也会收到商品 ID 和 Token。

验收标准：

- 首次启动和设置页列出两类第三方请求；
- 分析前可查看即将发送的数据摘要；
- 说明 macOS、Android、iOS、Windows 的 Key 存储差异；
- 明确本地业务记录和 JSON 导出是否加密；
- 不使用“所有数据不会离开设备”一类绝对表述。

## Deep-grill 结论

### 核心闭环

闭环已存在，但入口依赖易变的电商页面、用户 API Key 和模型兼容性。自动导入失败时必须把手动确认设计成正常降级，而不是失败后的补救。

### 个人 Agent

当前是按名称和价格挑选最多五条历史摘要的可解释检索器，不是训练或微调出来的 Agent。完成分类、物品库、结构化反馈和可确认规律前，应避免“训练自己的 Agent”表述。

### 本地与隐私

“本地保存”成立，“完全离线”或“数据绝不离开设备”不成立。模型和商品接口请求边界必须主动说明。

### 跨平台

四个平台具备共享源码能力，但消费者交付程度不同：Android、macOS、Windows有安装包，iOS仍需源码自签；Windows也缺少 OCR、分享入口、通知和文件导出。

## 推荐实施顺序

1. 完整数据清除；
2. SQLite/Drift 与旧数据迁移；
3. 数据导入和恢复；
4. 模型兼容层；
5. 隐私说明与发送前摘要；
6. 结构化反馈和购买后提醒；
7. 商品分类、物品库和可确认规律；
8. 解析稳定性与多平台 CI；
9. 无障碍、签名和分发体验。
