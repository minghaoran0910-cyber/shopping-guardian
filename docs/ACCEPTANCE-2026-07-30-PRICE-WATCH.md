# 购物守护者 1.8.8 价格监测验收

## 本轮范围

- 用户可以在单件淘宝或京东商品的分析结果中自行开启目标价监测。
- 价格只读取用户配置的 JustOneAPI；无价格、非法价格或请求失败时不生成虚假记录。
- 本地保存目标价、最近价格、检查时间、错误和价格快照。
- 首次达到目标价时发送通知；价格持续低于目标价时不重复提醒，回升后再次跌破才重新提醒。
- “稍后再看”支持手动检查、暂停、恢复和删除监测。
- 应用启动时只检查超过 6 小时未更新的监测，降低 API 消耗。
- 价格监测和历史快照随 schema 5 数据备份导出、预览并导入；API Key 仍不导出。

## deep-grill 发现并修复

1. SQLite 的替换写入会触发级联删除，导致历史价格丢失。已改用冲突更新，并用连续四次观测验证历史保留。
2. 新监测若首次检查时已经达到目标价，旧逻辑不会提醒。已把“从未检查”视为首次命中。
3. 每次启动都查价会浪费用户额度。自动检查增加 6 小时新鲜度门槛，手动检查仍立即执行。
4. 小屏价格卡片同时放开关和删除按钮会挤压商品名。已收进单个管理菜单。
5. schema 5 备份原先没有在导入预览和结果中说明价格监测数量。已补充数量与冲突提示。

## 明确边界

- PriceDive 的价格抓取函数是随机价格占位实现，本项目没有复制该实现，只参考本地快照与阈值触发的数据流。
- 当前没有可靠的全网多年历史价格数据，因此不能声称“历史最低价”；只记录用户开始监测后的本地价格。
- 当前可靠触发点是手动检查和应用启动检查。Android/iOS 可能限制后台任务，本版本不承诺价格变化后立即通知。
- 淘宝、京东链接必须能解析出稳定商品 ID；拼多多和购物车聚合链接暂不支持自动监测。
