# 购物守护者 1.9.3 价格提供层验收

## 本轮范围

- 将真实价格读取从监测服务中拆出为可替换的 `PriceProvider`。
- 默认通过 JustOneAPI 查询淘宝、天猫和京东稳定商品 ID。
- 每次报价记录价格、采集时间、来源和商品匹配置信度。
- 价格记录随本地备份导出和导入，备份格式升级至 v7。
- v1 至 v6 数据库可以迁移到 v7；旧记录的置信度保持未知，不伪造可信度。
- 只有匹配置信度不低于 80% 的报价可以更新可信当前价和触发目标价提醒。

## 参考 PriceDive 后保留与舍弃的部分

PriceDive 值得参考的是“定时采集、本地 SQLite 留存、比较价格变化”的数据流。
其公开说明也明确指出默认版本使用模拟价格，真实抓取需要自行实现网页解析，所以本项目没有复制其模拟价格或脆弱的页面抓取逻辑。真实报价继续由用户配置的 API 提供，并通过统一提供者接口进入本地价格账本。

## deep-grill 发现并修复

1. 只有价格数值不足以证明是同一商品，因此报价必须同时携带来源、时间和匹配置信度。
2. 上游没有独立回传可核验的标准商品 ID，JustOneAPI 报价记为高置信度 `0.9`，而不是伪装成 `1.0`。
3. 低置信度报价若直接参与提醒，可能把其他商品的价格误判为降价；现在仅留痕并显示错误。
4. 旧价格记录没有置信度证据，迁移后保持 `null`。
5. 从 v1 跨版本迁移会按最新结构创建价格表，随后再次添加新列；已限制为仅对既有 v5/v6 表执行加列。
6. 通过注入替代提供者的契约测试，确认更换数据源无需修改监测与通知逻辑。

## 明确边界

- 当前版本记录的是从用户开始监测后的本地价格，不声称是全网历史最低价。
- 会员、优惠券、国补、地区和 SKU 差异尚未形成可验证的统一口径。
- 系统后台调度受 Android、iOS 和桌面系统限制，不能承诺价格变化后立即通知。
- PriceDive 仅作为架构参考，不作为真实价格来源。
