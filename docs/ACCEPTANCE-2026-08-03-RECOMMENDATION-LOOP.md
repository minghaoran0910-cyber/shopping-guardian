# 推荐闭环 LOOP 验收

日期：2026-08-03

## deep-grill 结论

现有实现已经覆盖手动维护现有物品、历史清单输入、订单截图 OCR 预览、确认偏好、本机价格账本和消费人格分享卡，但“功能存在”不等于推荐闭环可靠。

本轮最强失败场景是：用户想买新耳机，物品库里同时有旧耳机和键盘；两者都属于“数码”。旧逻辑会把整个粗分类自动送给模型，或者在未填写分类时完全不引用旧耳机。即使模型没有判断替代、补充或重复，也可能直接返回购买建议。

## 本轮修复

- 分析表单展示当前仍在使用或备用的物品，分类只负责自动预选。
- 用户可逐项保留真正相关的现有物品，例如只选择当前耳机、排除同属数码的键盘。
- 手工选择优先于分类自动匹配；未选择的物品不进入模型请求。
- 已提供现有物品但模型返回 `ownership_relation=insufficient` 时，本地守卫把 `buy` 降级为等待。
- 最终参与对照的物品摘要继续固化在决策记录，之后可追溯当时依据。
- 消费人格卡增加 Android、iOS、macOS、Windows 系统分享面板；仍保留“保存分享卡”，作为取消分享或平台能力不可用时的降级路径。

## 证据边界

- “近期低价”目前仍是本机开始监测后的可信 30 天低价，不是全网多年历史低价。
- 偏好只来自至少三条已确认购买且带购后反馈的同类证据，并需用户确认后才进入模型。
- 消费人格是可编辑娱乐性总结；默认分享卡不含商品、金额、订单和模型配置。
- 粗分类仍然存在，显式选择缓解了误匹配，但细粒度商品类型仍是后续任务。
