# 购物守护者 1.9.2 模型候选事实验收

## 本轮范围

- 模型响应可选返回最多 3 条候选事实，每条必须包含事实短句和本次输入中的直接依据。
- 旧模型不返回该字段时保持兼容，不影响购买建议。
- 过滤无依据、超长、重复和格式错误的候选事实。
- 结果页逐条展示事实与依据，默认全部不勾选。
- 用户勾选的事实保存为 `confirmed`，未勾选的保存为 `candidate`。
- 候选项可在“习惯”页再次确认、修改或忽略。
- 相同事实使用稳定 ID；已经确认或忽略的事实不会被后续模型结果覆盖。
- 模型分析只通过 `PatternStore.readConfirmedTexts()` 读取已确认文本。

## deep-grill 发现并修复

1. 候选事实不能成为模型响应必填字段，否则旧模型和本地模型会失效，因此保持可选。
2. 只有事实没有依据会造成无法审计的画像污染，因此无 evidence 的项目直接丢弃。
3. 默认勾选会诱导用户被动确认，因此所有候选项默认关闭。
4. 首页自行过滤状态容易在未来改动中泄漏候选事实，因此将过滤下沉到存储层的单一方法。
5. 用户已经忽略或确认的事实必须优先于模型，稳定 ID 防止它反复出现或被覆盖。

## 明确边界

- 用户确认代表“愿意让应用在后续建议中使用”，不代表事实经过客观验证。
- 候选事实只在用户保存本次购买决定后进入本地待确认区。
- 本功能不是心理测评，也不会自动生成可分享画像。
