# 购物守护者 1.8.9 已有物品与推荐上下文验收

## 本轮范围

- “习惯 → 我的物品”支持手动添加、修改和删除已有物品。
- 提供数码、服饰、家居、兴趣收藏、运动、美妆护理和其他分类模板。
- 状态区分仍在使用、备用/收藏、已淘汰/转卖、已退货和现状不确定。
- 只有“仍在使用”和“备用/收藏”会进入同类推荐上下文。
- 已确认购买且分类相同的决策记录也会参与，和手动物品同名时优先采用手动维护的状态。
- 分析页提供相同分类的快速入口；发送模型前明确展示同类已有物品。
- 模型提示明确要求判断候选商品是在替代、补充还是重复购买，没有证据时不得猜测。
- 决策记录单独保存本次引用的已有物品，可在历史详情中追溯。
- schema 6 数据备份包含已有物品及引用；API Key 仍不导出。

## deep-grill 发现并修复

1. 旧“我的物品”只是购买记录的投影，无法表示用户早已拥有或物品已淘汰。本轮建立独立本地事实表。
2. 不能把买过等同于现在拥有，因此增加状态，并严格限制进入上下文的状态。
3. 保存弹窗时，箭头式 `setState` 错误返回 Future，Flutter 会拒绝刷新；同时修复了规律页和价格监测页的同类潜在问题。
4. 弹窗关闭动画期间提前销毁输入控制器会触发崩溃；已调整生命周期。
5. 小屏分类选择采用可换行模板；删除物品增加确认，避免误删改变推荐证据。

## 仍然明确的边界

- 分类匹配使用用户选择的统一模板，不依靠模型猜分类。
- 手动物品是用户陈述的本地事实，不代表已验证的订单。
- 本轮没有实现订单截图导入；ORDER-01、ORDER-02 仍按路线图继续推进。
