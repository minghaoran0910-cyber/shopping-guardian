# 购物守护者 1.9.5 目标价通知验收

## 本轮范围

- 参考 PriceDive 的本地价格账本、定期采集和变化触发思路，不复制其模拟报价或网页爬虫。
- 用户在分析结果中自行决定是否监测，并可编辑目标价。
- 应用启动或回到前台时检查超过 6 小时未更新的监测；“稍后再看”页仍可立即手动检查。
- 同一商品的可信报价首次进入目标区间时发送价格通知，明确提示“达到目标价，可以考虑下单”。
- 冷静期、价格命中和购买后回访使用不同通知语义。

## deep-grill 发现并修复

1. Dart 层虽然创建了目标价提醒，但 Android、iOS 和 macOS 原生层把所有通知都展示成“冷静期结束”。现在通知携带明确类型，三端分别生成正确文案。
2. 原有自动检查只发生在应用冷启动。现在应用从后台回到前台也会限频检查，避免长时间驻留后不更新。
3. 保存监测后没有明确反馈。现在会提示监测已开始以及达到目标价后的行为。
4. 价格持续低于目标价时仍保持去重；只有回升后再次跌破才会重新提醒，避免骚扰。

## 证据边界

- PriceDive 的公开说明明确写明默认版本使用模拟价格，真实价格需要自行实现抓取。本项目的真实报价仍来自用户自行配置的 JustOneAPI，并要求商品匹配置信度不低于 80%。
- 本地应用无法承诺被系统完全挂起时持续联网。当前可靠触发点是启动、回到前台和手动检查；通知发生在这些检查发现可信报价达到目标价之后。
- 本地记录只代表开始监测后的价格，不声称是全网历史最低价。

## 自动验收

- 通知协议测试验证价格提醒携带 `kind: price`，冷静期和购买后回访不会混用文案。
- 价格监测回归覆盖首次命中、持续低价去重、回升后再次跌破、低置信度不提醒、通知被拒绝不标记成功。

- `flutter analyze`：0 issue（在临时英文路径执行，规避中文工程路径的分析器问题）。
- Android debug APK、iOS 模拟器和 macOS debug 构建全部通过。
