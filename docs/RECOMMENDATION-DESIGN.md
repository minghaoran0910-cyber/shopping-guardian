# 推荐与个人画像设计

本设计回答三个问题：用户现在有什么、这个价格是否值得、建议为什么适合这个用户。

## 一条建议需要的证据

1. **当前需求**：这次为什么想买、预算和时间要求。
2. **已有物品**：同分类仍在使用的物品，以及状态、使用频率和满意度。
3. **历史行为**：买过、退货、淘汰、后悔和没买的记录。
4. **价格证据**：同一平台同一商品的带时间价格观测。
5. **确认偏好**：只使用用户确认过的规律，不把模型猜测直接当事实。

模型负责解释这些证据，不负责发明证据。

## 已有物品与历史订单必须分开

订单截图只能证明“可能买过”，不能证明“现在仍拥有”。导入后每件商品都要确认状态：

- 仍在使用
- 备用/收藏
- 已淘汰或转卖
- 已退货
- 只买过，不确定现状

同类推荐只把“仍在使用”和“备用/收藏”作为当前基线；其他状态可以作为历史偏好或踩坑证据。

## 历史价格的现实边界

JustOneAPI 当前商品详情接口可以返回当下价格（可用时），官方文档建议通过定时采集来监控价格变化，但没有给现有接入提供一条可直接读取多年历史价格曲线的标准接口。

PriceDive 的 MIT 开源实现提供了一个值得借鉴的数据流：在本地保存价格快照，比较价格变化，再由计划任务触发提醒。但它当前仓库里的 `fetch_price()` 是随机价格占位实现，并不具备真实电商查价能力。本项目只参考其本地快照和阈值触发结构，真实价格仍来自用户配置的 JustOneAPI。

因此首个可靠版本采用两层方案：

- 本地价格账本：每次导入、分析或用户主动刷新时，记录商品 ID、平台、价格、时间和来源。数据越用越完整。
- 可替换数据提供器：以后可由用户自己选择历史价格服务；没有配置时不向第三方发送额外请求。
- 目标价提醒：只在价格首次从目标价上方进入目标区间时提醒；价格回升后再次跌破才会重新提醒，避免每次检查都推送。

刚开始跟踪的商品只能说“当前价”和“本地开始记录后的低价”，不能冒充全网历史低价。促销券、会员价、国补和不同 SKU 必须单独标识，不能直接混为同一价格。

## 推荐输出

每次建议按固定顺序展示：

1. 是否解决一个真实需求。
2. 与已有同类物品相比，新增了什么或替代了什么。
3. 对预算和消费规则的影响。
4. 当前价格证据，以及证据是否足够判断时机。
5. 与已确认偏好的关系，同时列出反例。
6. 建议买、等、放弃或寻找替代，以及仍缺什么信息。

## 消费人格分享

消费人格是娱乐性总结，不是心理测评。生成前允许用户编辑，分享图默认只包含：

- 一个趣味名称
- 3 个已确认特点
- 1 个提醒
- 可选的应用名称和开源项目地址

默认不包含商品名、金额、订单、商店、API 地址、密钥或原始截图。证据不足时先做一个可单独完成的小测试，不用两三笔购物记录强行给用户定型。

## 实施顺序

1. 多商品逐件决策（已完成）。
2. 已有物品和历史订单事实层。
3. 订单截图导入与人工确认。
4. 同类已有物对比。
5. 本地价格账本与来源标记。
6. 已确认偏好参与建议。
7. 消费人格和隐私安全分享卡。

## 验收底线

- 删除或修改已有物品后，下一次分析不能继续引用旧状态。
- 订单 OCR 结果必须先预览，不能自动进入画像。
- 没有可靠价格证据时必须显示“数据不足”。
- 未确认偏好不得进入模型请求。
- 分享卡不得泄露业务明细或配置。
