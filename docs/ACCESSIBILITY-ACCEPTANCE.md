# 真机无障碍验收

更新日期：2026-07-28

自动化测试负责发现语义标签、触控尺寸、键盘焦点和文字溢出问题，但不能证明读屏顺序、播报是否自然，也不能替代真实手势操作。发布候选版本必须按本文分别完成 TalkBack 与 VoiceOver 验收。

## 验收环境

每个平台至少记录一台真实设备：

| 字段 | Android | iOS |
| --- | --- | --- |
| 应用版本与提交 | 必填 | 必填 |
| 设备型号 | 必填 | 必填 |
| 系统版本 | 必填 | 必填 |
| 读屏版本 | TalkBack 版本 | VoiceOver（随系统） |
| 字号/显示缩放 | 默认及 200% | 默认及最大辅助字号 |
| 验收人和日期 | 必填 | 必填 |

使用 release 构建验收。Android 应安装待发布 APK；iOS 应使用与候选提交一致的 Xcode 真机构建。不得用模拟器结果代替。

## 统一通过标准

每个步骤必须同时满足：

1. 焦点顺序与视觉阅读顺序一致，没有焦点陷阱或无法到达的控件。
2. 按钮、输入框、状态和错误信息有明确名称；不只播报“按钮”“图片”或内部图标名。
3. 同一信息不被重复播报，装饰图不抢占焦点。
4. 操作后能感知结果；加载、失败、导入完成和分析完成不会静默变化。
5. 不依赖颜色、位置或拖拽才能完成核心流程。
6. 默认与放大字号下均可完成任务，没有被遮挡的主要操作。

任意一步失败时，记录实际播报、预期播报、截图或录屏时间点，并创建 Issue；不得将整项标记为通过。

## A11Y-03 验收流程

### A. 首次启动与设置

- [ ] A01 启动应用，依次读出三步首次引导，标题、说明和当前步骤可理解。
- [ ] A02 使用读屏手势跳过引导，再重新进入设置。
- [ ] A03 切换浅色/深色与中文/英文，选中状态会被播报。
- [ ] A04 找到模型 Endpoint、模型名和 API Key；密码内容不被读出。
- [ ] A05 故意提交无效配置，错误信息会自动成为可感知内容。

### B. 分享与导入

- [ ] B01 从淘宝或京东分享一条商品文字到应用，焦点落到可继续操作的位置。
- [ ] B02 粘贴单商品分享文字并进入预览，读出平台、标题、价格、数量和完整度。
- [ ] B03 导入一张购物车截图，系统照片/文件选择器可由读屏完成。
- [ ] B04 编辑一个识别错误的标题或价格，状态从“待确认”变为“已确认”且可感知。
- [ ] B05 制造一次解析失败，提示包含用户下一步能做的动作。

### C. 分析与决策

- [ ] C01 填写购买理由、预算和补充信息，字段标签不会与当前值混淆。
- [ ] C02 打开发送前预览，能逐项确认将发送给模型的内容并取消。
- [ ] C03 开始分析，加载状态可感知且不会把焦点永久锁住。
- [ ] C04 读出结论、理由、风险和建议；四种决策操作名称明确。
- [ ] C05 选择“等待”，可读出冷静期截止时间和保存结果。

### D. 历史、习惯与数据

- [ ] D01 浏览历史列表及详情，时间线顺序和当前状态清晰。
- [ ] D02 填写购买后反馈，包括使用频率、满意度和后悔原因。
- [ ] D03 浏览个人物品和候选规律，确认、编辑、忽略、删除均可完成。
- [ ] D04 导出数据或诊断，系统保存界面可由读屏完成。
- [ ] D05 打开“清除全部数据”确认框，清除范围和不可恢复警告会被完整读出。
